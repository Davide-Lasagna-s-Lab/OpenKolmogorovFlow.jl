Indexing

OpenKolmogorovFlow.WaveNumber — Type
WaveNumber(k, j)

Fourier-mode identifier used for indexing FTField.

k is the signed wavenumber stored along the full complex FFT direction and j is the non-negative wavenumber stored along the real-to-complex FFT direction. Because the package stores an rfft half-plane, negative j modes are represented implicitly by Hermitian symmetry and are not valid indices.

Example

Ω = FTField(4, 6)
Ω[WaveNumber(-2, 1)] = 1 + 2im
source
OpenKolmogorovFlow.@loop_k — Macro
@loop_k n m expr

Loop over the signed active k wavenumbers -n:n while exposing both k and the storage index _k inside expr.

This macro is an internal convenience for allocation-free spectral loops. It keeps the signed wavenumber (k) available for formulas and the corresponding stored row (_k) available for direct FTField indexing.

source
OpenKolmogorovFlow.@loop_jk — Macro
@loop_jk n m expr

Loop over all explicitly stored active Fourier modes.

Inside expr, j and k are physical wavenumbers and _j, _k are their storage indices. The loop covers j = 0:n and k = -n:n, matching the package's active Fourier set.

Fields

OpenKolmogorovFlow.AbstractField — Type
AbstractField{m,T} <: AbstractMatrix{T}

Abstract matrix-like representation of a real physical-space field.

The type parameter m determines the uniform grid size 2m+2 in both periodic directions. Concrete fields are stored as ordinary matrices in the same orientation used by FFTW plans in this package.

source
OpenKolmogorovFlow.Field — Type
Field(data::AbstractMatrix{<:Real})
Field(m::Int, [T=Float64])
Field(m::Int, fun)

Physical-space scalar field on the periodic square.

Field(data) wraps a square, even-sized real matrix. The grid parameter is inferred from size(data,1) == 2m+2. Field(m, T) allocates a zero field, and Field(m, fun) evaluates fun.(x, y) on make_grid.

The object behaves as an AbstractMatrix; use parent(u) to access the underlying storage.

source
OpenKolmogorovFlow.make_grid — Function
make_grid(m::Int) -> (x, y)
make_grid(u::Field) -> (x, y)

Return broadcastable coordinate arrays for the periodic square [0, 2π)^2.

Both directions have 2m+2 points. The endpoint 2π is omitted so periodic functions are sampled without duplicating the first point.

source
OpenKolmogorovFlow.AbstractFTField — Type
AbstractFTField{n,m,T} <: AbstractMatrix{Complex{T}}

Abstract Fourier-space field with active cutoff n and storage cutoff m.

The field stores a real-to-complex Fourier half-plane of size (2m+2, m+2). Only modes with j = 0:n and k = -n:n are considered active by the solver. The remaining stored modes are available for dealiasing and are normally kept zero by FFT masking.

source
OpenKolmogorovFlow.FTField — Type
FTField(n::Int, m::Int, [T=Float64])
FTField(data::AbstractMatrix{Complex{T}}, n::Int)

Fourier-space vorticity field in packed rfft layout.

n is the largest active wavenumber used by spectral loops. m is the storage resolution and must satisfy m >= n. A larger m is used for dealiasing the nonlinear term while preserving an active mode set of size n.

Modes are usually accessed with WaveNumber:

Ω = FTField(8, up_dealias_size(8))
Ω[WaveNumber(2, 1)] = 0.5im

The zero and Nyquist-related modes are handled by the FFT masking/symmetry helpers; direct low-level edits should preserve the package's Hermitian symmetry assumptions.

source
OpenKolmogorovFlow.growto! — Function
growto!(OUT, U) -> OUT

Copy the active Fourier coefficients of U into OUT.

OUT must have storage resolution at least as large as U and an active cutoff at least as large as U's active cutoff. All coefficients of OUT are cleared before active modes are copied, so inactive/dealiased modes are zero in the result.

OpenKolmogorovFlow.ForwardFFT! — Type
ForwardFFT!(u::AbstractField; flags=FFTW.EXHAUSTIVE)

Reusable in-place forward FFT plan from Field to FTField.

Calling the plan writes Fourier coefficients into the supplied FTField, normalises by the number of physical grid points, applies the active-mode mask, and restores the stored Hermitian symmetry on the zero j column.

source
OpenKolmogorovFlow.InverseFFT! — Type
InverseFFT!(U::AbstractFTField; flags=FFTW.EXHAUSTIVE)

Reusable in-place inverse FFT plan from FTField to Field.

The input Fourier field is masked before FFTW executes. This is appropriate for solver caches where inactive modes are scratch storage; callers that need to preserve every stored coefficient should pass a copy.

Operators

OpenKolmogorovFlow.ddx! — Function
ddx!(OUT, U) -> OUT

Differentiate the Fourier-space field U along the x direction.

The derivative is applied spectrally by multiplying each active mode by im*j, following the package convention that j is the non-negative real-to-complex direction. OUT and U must have matching active and storage resolutions.

source
OpenKolmogorovFlow.ddy! — Function
ddy!(OUT, U) -> OUT

Differentiate the Fourier-space field U along the y direction.

The derivative is applied spectrally by multiplying each active mode by im*k, where k is the signed full-FFT wavenumber.

source
OpenKolmogorovFlow.laplacian! — Function
laplacian!(OUT, U) -> OUT

Apply the spectral Laplacian to U.

Each active Fourier coefficient is multiplied by -(j^2 + k^2). The zero mode is therefore mapped to zero.

source
OpenKolmogorovFlow.invlaplacian! — Function
invlaplacian!(OUT, U) -> OUT
invlaplacian!(OUT, U, c) -> OUT

Apply a diagonal inverse elliptic operator in Fourier space.

Without c, this computes $-Δ^{-1} U$ mode-by-mode and sets the mean mode to zero. With c, this computes $(I - cΔ)^{-1} U$ and also zeros the mean mode, matching the implicit time-stepping operator used by Flows.ImcA!.

Forward Equation

OpenKolmogorovFlow.ForwardExplicitTerm — Type
ForwardExplicitTerm(n, m, kforcing, flags, T)

Preallocated explicit nonlinear term for the forward vorticity equation.

This object owns Fourier and physical work arrays, plus reusable FFT plans. It computes advection, updates the CFL estimate β, and adds the built-in Kolmogorov forcing modes.

source
OpenKolmogorovFlow.ForwardEquation — Type
ForwardEquation(n, m, Re[, kforcing=4, flags=FFTW.EXHAUSTIVE,
                forcing=DummyForcing(n), T=Float64])

Forward vorticity equation for open Kolmogorov flow.

The equation combines the implicit viscous term, the explicit nonlinear advection and built-in Kolmogorov forcing, and an optional user-supplied forcing object. It follows the callable interface expected by Flows.jl.

source

Viscous linear term for the vorticity equation.

Forcings

OpenKolmogorovFlow.AbstractForcing — Type
AbstractForcing{n}

Supertype for additive forcing objects acting on fields with active cutoff n.

Forcing objects are callable and mutate the right-hand-side field passed as the last argument. Implementations may support the forward, tangent, or adjoint equation signatures depending on where the forcing is meaningful.

Hooks

OpenKolmogorovFlow.CFLHook — Type
CFLHook([CFL_max=1, Δt_min=0, Δt_max=1])

Time-step selection hook based on the CFL estimate stored by the explicit term.

The hook returns a clamped time step in the interval (Δt_min, Δt_max). For a single ForwardExplicitTerm, it reads the most recent advective time scale from β[1]; for a Flows.Coupled object, it uses the first equation.

laminarflow(n, m, Re, [kforcing=4]) -> FTField

Return the steady laminar vorticity field for the sinusoidal Kolmogorov forcing.

The returned field has active cutoff n, storage cutoff m, and nonzero coefficients only at WaveNumber(±kforcing, 0). The forcing wavenumber must be representable in the active mode set.

OpenKolmogorovFlow.radial_mean! — Function
radial_mean!(f, Ω, out, counts) -> out

Compute a radial average of f applied to Fourier coefficients.

out[r] accumulates the average over modes whose radius sqrt(j^2 + k^2) rounds to integer shell r. counts is a work vector used to store the number of modes in each shell. Both vectors are overwritten.
